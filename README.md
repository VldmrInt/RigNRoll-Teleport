# Телепорт / Teleport

[English instructions](README.en.md)

Клонируйте репозиторий в папку `Tools/Teleport` внутри установленной игры:

```powershell
git clone https://github.com/VldmrInt/RigNRoll-Teleport.git Tools/Teleport
Copy-Item Tools/Teleport/game-root.example.txt Tools/Teleport/game-root.txt
```

Укажите путь к игре в `game-root.txt`, затем запустите `Tools/Teleport/Teleport.bat`.

Запуск: двойной щелчок по `Teleport.bat`. Если игра уже запущена, закройте её перед запуском. Агент загружается только при старте игры; лаунчер сохраняет остальные параметры `JAVA_TOOL_OPTIONS`.

1. Загрузите сохранение или начните игру.
2. Через Alt+Tab переключитесь в окно «Rig'n'Roll — Телепорт».
3. Нажмите «Обновить точки» и на несколько секунд вернитесь в игру через Alt+Tab: свёрнутый движок может приостанавливать чтение карты. Снова откройте окно телепорта. Введите часть имени или тип объекта (например, «Склад»), выберите строку и нажмите «Переместиться».
4. Вернитесь в игру через Alt+Tab и снимите паузу, чтобы движок завершил перенос. Результат появится в окне телепорта.

Закрытие окна сворачивает его; агент работает до выхода из игры. После загрузки другого сохранения обновите список.

Переключатель `Русский / English` находится рядом с полем поиска. Он переводит окно, типы точек, стандартные описания, поиск и ошибки. Подробные авторские описания берутся из локализации самой игры. В английском режиме русскоязычный текст игры скрывается и заменяется английской пометкой и пояснением по типу точки.

В списке отображается игровое название точки и её исходный код. Под списком — подробное описание из локализации `MPLONG`, тип объекта и координаты. Поиск учитывает названия, описания и коды. Если игрового описания нет, показывается явная пометка и общее назначение типа объекта; точное назначение неизвестных точек не выдумывается.

Точки читаются из `MissionsMap` текущего мира: склады, бары, офисы, АЗС, СТО и сценарные места, зарегистрированные игрой. Бинарный `GAME.CNF` непосредственно не разбирается. Поэтому в списке есть только зарегистрированные точки, а не все объекты CNF. Названия сохраняются такими, какими их отдаёт движок.

Перенос использует штатный `actorveh.teleport` под `eng.lock`, обнуляет скорость перед переносом и ждёт callback `MakeTeleport`. После callback проверяются фактические координаты машины. GUI работает в Swing, игровые операции — в отдельном потоке. При ошибке или тайм-ауте повторная команда автоматически не отправляется.

Каталог инструмента: `Tools/Teleport`. Скопируйте `game-root.example.txt` в `game-root.txt` и укажите в нём корневую папку игры. Готовый `Teleport.jar` уже включён; для пересборки нужен JDK 21 через `JAVA_HOME` или `PATH`. Сборка: `powershell -ExecutionPolicy Bypass -File Tools/Teleport/build.ps1`. Self-test: аналогично `Tools/Teleport/test.ps1`; тесты выполняются на встроенной Java 5.

Журнал `teleport.log` находится в `Tools/Teleport` при запуске из корня или из `MonsterCup`. Если инструмент хранится вне папки игры, журнал создаётся в рабочей папке игры (`MonsterCup`). При установке игры в `Program Files` Windows может перенаправить его в `%LOCALAPPDATA%\VirtualStore\Program Files (x86)\1C\RigNRoll\MonsterCup\teleport.log`. Записываются имя точки, координаты до/после и ошибки.

Ограничения: координаты объектов не гарантируют свободную площадку; последствия для активного задания, гонки и прицепа определяются штатным телепортом игры. Файлы сохранений инструмент не редактирует.
